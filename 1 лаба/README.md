# Лабораторная работа № 1. Групповой чат в оперативной памяти

## Цель

Реализовать потокобезопасный групповой чат на Java, все данные которого живут
только в оперативной памяти, и покрыть основной сценарий автоматическими тестами.

## Возможности

- подключение и отключение пользователей;
- хранение признака «в сети», времени последнего подключения и настройки уведомлений;
- отправка сообщения всем пользователям, которые находятся в сети и включили уведомления;
- запрос полной истории чата, в том числе пользователем с выключенными уведомлениями;
- безопасная одновременная работа пользователей из разных потоков;
- проверка некорректных операций и входных данных.
- консольная форма для ручной проверки всего функционала.

Публичный контракт программы — интерфейс `GroupChat`. Реализация
`InMemoryGroupChat` хранит состояния, историю и очереди входящих сообщений в
коллекциях Java. После завершения процесса данные пропадают.

Сообщение доставляется и отправителю, если он находится в сети и его уведомления
включены: отправитель является таким же подключенным участником группового чата.
Метод `receiveMessages` возвращает накопленные сообщения и очищает входящую
очередь пользователя.

## Структура

```text
src/main/java/ru/study/chat/
├── GroupChat.java             — пользовательский интерфейс
├── InMemoryGroupChat.java     — реализация в оперативной памяти
├── ChatMessage.java           — неизменяемая модель сообщения
├── UserState.java             — неизменяемый снимок состояния пользователя
└── Main.java                  — консольная форма

src/test/java/ru/study/chat/
└── InMemoryGroupChatTest.java — модульные и многопоточный тесты
```

## Запуск тестов

Требуются Java 17 или новее и Maven 3.9 или новее.

```shell
mvn test
```

Набор тестов следует сохранять и расширять в следующих лабораторных работах.

## Ручная проверка

Соберите и запустите приложение:

```shell
mvn package
java -jar target/in-memory-group-chat-1.0-SNAPSHOT.jar
```

В консоли появится нумерованное меню. Можно подключить несколько пользователей,
выключить одному из них уведомления, отправить сообщение от другого пользователя,
а затем отдельно проверить входящие сообщения, историю и состояния участников.
